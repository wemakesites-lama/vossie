# Role bars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The phone's main bar fits who is signed in: students keep Sell and Saved, sellers get My shop and Messages, mentors Mentoring and Messages, admins Today and Messages (spec `docs/superpowers/specs/2026-10-26-role-bars-design.md`, decision 92).

**Architecture:** A pure `barFor(account)` decides the bar. Slots 3 to 5 of `TabBar` become one streamed Server Component, `RoleTabs`, whose `<Suspense>` fallback is today's signed-out Sell, Saved and You, so the static shell stays the same for everyone. Badges come from the readers their lists use. A streamed `PhoneSaved` brings the Saved heart back to the phone header for every bar but the student one.

**Tech Stack:** Next.js 16.4 App Router (Cache Components), React 19.3 Server Components, Tailwind 4.3, Vitest 5 + Testing Library, Playwright + axe. pnpm only.

## Plan decisions (where this plan departs from or sharpens the spec)

1. **One streamed piece for slots 3 to 5.** `RoleTabs` renders the pill, slot four and You, replacing `TabAccount`. One `getViewer()` and one `readForYou` serve all three, and You's badge needs to know whether the bar has Messages anyway. `TabBar`'s `account` prop becomes `tail`.
2. **`barFor` reads `account.seller`.** `Account.seller` is non-null for any account with a shop, pending and declined included, and carries `sellerSlug` (null while pending). So no `getShopOf` call is needed, and a pending shop's My shop has no badge (it has no queue yet, as `SellBar` already treats it).
3. **The header's account icon is unchanged.** It shows only from the tablet step (`AccountLink.tsx`: "Phones have the tab bar's You tab instead"), where there is no bar, so it keeps For you's full total. The spec's sentence about the header icon on phones is dropped. Spec section 7 is updated in Task 7.
4. **Messages counts For you's `messages`, `sales` and `offers` rows.** Sales to confirm open `/messages` too (`lib/you/model.ts`), so leaving them out would count them under You and not under the tab that opens them. These three rows are `MESSAGE_ROWS`.
5. **Today's badge sums the admin bar's three counters** (`countWaitingShops`, `openReportCount`, `openBookingCount`). That is exactly `todayQueue`'s `waiting` (shops, reports and slot requests; Hidden isn't counted) without reading four full lists on every page an admin opens. The admin bar's badges already come from these counters.
6. **My shop's badge is the sum of `sellerNeeds(queue, now)`**, what `/sell`'s Needs you card lists, after `connection()` (it reads the clock).

```ts
import { ADMIN_PATH, MENTOR_PATH } from "@/lib/staff/paths";
import { canUse } from "@/lib/staff/roles";
import type { Account } from "@/lib/types";

// Which main bar an account gets on phones (role bars spec 4, decision 92). The only place that decides: the tab bar
// and the header's phone heart both ask it. The highest role wins: admin, then mentor, then seller, then student.

export type BarKind = "student" | "seller" | "mentor" | "admin";

/** Signed out is "student". A shop in any state, pending and declined included, makes a seller: /sell is their home. */
export function barFor(account: Pick<Account, "roles" | "seller"> | null): BarKind {
  if (!account) return "student";
  if (canUse(account, "admin")) return "admin";
  if (canUse(account, "mentor")) return "mentor";
  return account.seller ? "seller" : "student";
}

/** The centre pill for each bar but the student one (whose pill is Sell): the role's workspace. */
export const ROLE_PILLS: Readonly<Record<Exclude<BarKind, "student">, { label: string; href: string }>> = {
  seller: { label: "My shop", href: "/sell" },
  mentor: { label: "Mentoring", href: MENTOR_PATH },
  admin: { label: "Today", href: ADMIN_PATH },
};
```

```ts
/** For you's rows that open Messages (role bars plan decision 4): new messages, sales to confirm and new offers. */
export const MESSAGE_ROWS: ReadonlySet<string> = new Set(["messages", "sales", "offers"]);

/** The Messages tab's badge, on bars that have one: For you's message rows (role bars spec 7). */
export function messagesTotal(items: readonly Pick<NeedsYouItem, "key" | "count">[]): number {
  return forYouTotal(items.filter((item) => MESSAGE_ROWS.has(item.key)));

/** You's badge beside a Messages tab: For you without the message rows, so a new message counts once. */
export function othersTotal(items: readonly Pick<NeedsYouItem, "key" | "count">[]): number {
  return forYouTotal(items.filter((item) => !MESSAGE_ROWS.has(item.key)));
}
```

The pill badges:

```tsx
const PILL_ICONS: Readonly<Record<Exclude<BarKind, "student">, ReactNode>> = {
  seller: <StoreIcon />,
  mentor: <UserIcon />,
  admin: <GridIcon />,
};

const orNull = <T,>(read: Promise<T>) => read.catch(() => null);

/** The pill's count from the reader its page lists (role bars spec 7, plan decisions 5 and 6), or null. */
async function pillBadge(kind: Exclude<BarKind, "student">, sellerSlug: string | null): Promise<Badge> {
  if (kind === "seller") {
    if (!sellerSlug) return null; // A pending shop has no queue yet.
    await connection(); // sellerNeeds reads the clock for its ages.
    const queue = await orNull(queueFor(sellerSlug));
    if (!queue) return null;
    const count = forYouTotal(sellerNeeds(queue, new Date()));
    return { count, words: plural(count, "thing needs you", "things need you") };
  }
  if (kind === "mentor") {
    const count = await orNull(openBookingCount());
    return count === null ? null : { count, words: plural(count, "slot request waiting", "slot requests waiting") };
  }
  const [shops, reports, slots] = await Promise.all([
    orNull(countWaitingShops()),
    orNull(openReportCount()),
    orNull(openBookingCount()),
  ]);
  if (shops === null || reports === null || slots === null) return null;
  const count = shops + reports + slots;
  return { count, words: "waiting" };
}
```

`forYouTotal` sums `count` over any `{ count }` list, so it sums `sellerNeeds`' rows too. If its parameter type rejects `SellerNeed`, sum inline: `sellerNeeds(queue, new Date()).reduce((sum, need) => sum + need.count, 0)`.

`RoleTabs`, replacing `TabAccount`:

```tsx
/**
 * Slots 3 to 5 for this request's session (role bars spec 5, plan decision 1): Sell, Saved and You for a student or
 * a signed-out visitor; for a seller, mentor or admin, the role's pill (its workspace) and Messages, then You.
 * Request-time, so the layout puts it inside <Suspense> with StudentTail as its fallback. A failed lookup counts as
 * signed out and a failed count shows no badge, never a guess (role views spec 4.2). getViewer and readForYou are
 * each read once per request, shared with the header and the You page.
 */
export async function RoleTabs() {
  const account = await getViewer().catch(() => null);
  if (!account) return <StudentTail />;
  const kind = barFor(account);
  const read = await readForYou(account.id).catch(() => null);
  const items = read?.items ?? [];
  if (kind === "student") return <StudentTail account={<AccountTab signedIn forYou={forYouTotal(items)} />} />;

  const pill = ROLE_PILLS[kind];
  const badge = await pillBadge(kind, account.seller?.sellerSlug ?? null);
  const messages = read ? messagesTotal(items) : 0;
  return (
    <>
      <li>
        <Tab
          href={pill.href}
          icon={PILL_ICONS[kind]}
          label={pill.label}
          match="section"
          prefetch={false}
          className="tab tab-sell"
          describedBy={badge && badge.count > 0 ? "tab-pill-count" : undefined}
        >
          {badge && badge.count > 0 && <TabBadge id="tab-pill-count" count={badge.count} words={badge.words} />}
        </Tab>
      </li>
      <li>
        <Tab
          href="/messages"
          icon={<MessageIcon />}
          label="Messages"
          prefetch={false}
          describedBy={messages > 0 ? "tab-messages-new" : undefined}
        >
          {messages > 0 && (
            <TabBadge id="tab-messages-new" count={messages} words={plural(messages, "new message", "new messages")} />
          )}
        </Tab>
      </li>
      <li>
        <AccountTab signedIn forYou={othersTotal(items)} others />
      </li>
    </>
  );
}
```
